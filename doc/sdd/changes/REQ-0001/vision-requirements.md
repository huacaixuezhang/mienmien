# REQ-0001 vision-requirements

## 愿景

- 目标：完成 MienMien 项目初始化治理基线，建立可执行的 CLA 门禁、简化 SDD 流程、跨平台架构约束与文档归档体系。
- 业务价值：降低协作与合规风险，保证社区贡献可审计、可管控，支撑后续持续迭代。
- 成功指标：
  - CLA 与 SDD 门禁规则在仓库中可执行；
  - 规则、技能、模板、治理目录全部落地；
  - 文档中无关键流程冲突与核心占位符残留。

## 需求

- 功能需求（FR）：
  - FR-001：必须有 CLA 强制门禁，未签署不可合并；
  - FR-002：必须采用简化 SDD（单变更目录 + 双文件）；
  - FR-003：必须定义 Java/ios/android/web 架构约束；
  - FR-004：必须提供治理资料目录（签名、收益、分配、费用、邮件模板）。
- 非功能需求（NFR）：
  - NFR-001：治理文档统一中文，术语可保留英文标准名；
  - NFR-002：流程可审计，关键记录可追溯；
  - NFR-003：门禁规则可在 GitLab 主仓执行，并兼容 GitHub 镜像。
- 范围内：
  - 规则文件、技能文件、治理文档、CI 门禁文件、目录结构初始化。
- 范围外：
  - 业务功能开发；
  - 真实年度收益/奖金数据填报；
  - GitLab 后台人工开关配置本身（需维护者在平台操作）。

## DDD 要点（Java 后端适用）

- 限界上下文：
  - `java/business`（B 端后端域）
  - `java/consumer`（C 端后端域）
- 聚合根：
  - 在具体业务开发阶段按需求定义，本次初始化不引入业务聚合实现。
- 关键不变量：
  - Java 后端代码必须遵循 DDD 分层（domain/application/infrastructure/interfaces）；
  - Java 代码规范以《阿里巴巴 Java 开发手册》为基线。
